# 編集基準（静的部分。運営が編集する。回答と差し戻し理由のログは Worker が後ろに足す）

## 素材の考え方
- 素材は「子どもごとの完成した授業」ではなく、バディエージェントが組み替えて使う部品の箱。再利用できる形で作る
- 最初に触れるものがあり、説明はその後。説明より先に、見る・触る・試す・作る。問いは答えより先
- **学校っぽくしない。** 目標・ねらいを示してやらせる書き方をしない。面白さから入り、手を動かして自分で気づく形にする。何に気づくと面白いかは、子どもには見せない「面白さの芯」としてバディに渡す
- 本文は中学生向けに 1 本（600 字が目安）。小学生への言い換え・短くすること・関心に合わせた入口選びはバディがする。工場は組み替えの材料（事実カード・問いの種・入口・変えてよい範囲）をそろえる
- 体験・やり取り・遊びの形（お題・クイズ）は、それがあると分かることが増える題材だけ。毎回クイズを付けない
- 15〜30 分で触れ切れる大きさにする。続き・別の場面で使う候補を 1 つ添える

## 根拠
- 一次資料（公式ドキュメント、公式 wiki、公的機関）を優先する。X や Web の事例は発想の入口であって根拠ではない
- 確か / 仮説 / 未確認 を分ける。簡略化で意味が変わる時は仮説側に倒す
- 「確認済み」は書かない。確認は人が付ける

## 言葉
- 呼び名は「バディエージェント」。「達成率」は使ってよい
- 子ども向け本文で使わない語: 点数、ランキング、順位、評価、成績、レベル、集中力、得意、苦手、上手、成長、データがありません、学びのバディ
- 目標の言い回しを使わない（機械検査の一覧は契約 §AL-3 が正本。次の行と同じ）。学びの目標を示す意味での「目標」「ねらい」も使わない
  目標語（正本）: 学習目標 / めあて / 学ぼう / 学びましょう / 学習しましょう / 覚えよう / 覚えましょう / 身につけよう / 身につけましょう / できるようになろう / できるようになりましょう / 理解しよう / 理解しましょう / マスターしよう / この単元 / 本時 / 目標は / 目標： / 目標: / ねらいは / ねらい： / ねらい:
- 「できない」と決めつけない。「A だから B はできない」としない

## 安全と条件
- 刃物・火・屋外・生き物・高所を含む活動は needs_supporter_check を true にする
- 道具・場所・対象年齢・サポーターの確認が要るかを conditions に書く

## 版が決まっている題材（Minecraft など）
- うちで使う Minecraft は Java 版。Minecraft の素材は Java 版の最新の正式版を基準に作り、使う条件（conditions.tools）に版を書く
- 情報は edition（Java 版 / 統合版）ごとに分けて集める。統合版の仕様を Java 版の事実として書かない。違いがある所は Java 版の事実だけを書き、必要なら「統合版ではちがうことがある」と 1 文添える
- 古い情報を根拠にしない。動画は公開日が 3 年以内のもの。Web の出典も、今の版で変わっていないことを確かめる
