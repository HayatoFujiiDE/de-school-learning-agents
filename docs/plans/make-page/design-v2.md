## 1. 一文と範囲

**利用者がしたいこと**: まだ何を作るか決まっていなくても、見本や案を触るところから始めて、変えた結果を確かめながら形にし、残したいものを作品にする。

| 担う | 担わない（担う場所） |
| - | - |
| アイデアを練る・比べる・試作する・制作する（AI／人と分担）・作品に残す・再編集 | 日常会話・相談の起点（**話す**。作るの中の相談は「この活動について」に限る） |
| 制作中の活動の一覧と再開 | 完成品を眺める・見せる・公開する（**作品**。保存と公開は別操作: 引き継ぎ 143行） |
| 変えたこと → 結果、AI／人が担った部分の記録 | 過去の発見・会話をたどる（**あしあと**）、止まった場所へ戻る共通導線（**続きをする**） |
| 今日の予定を開く入口（共通ボタン） | 予定の編集（**今日の予定**） |

## 2. 概念（最小の単位）

［事実］v1.0 702〜719行の「活動」「作品」の持ち物に従う。［提案］モックで持つ形:

| 単位 | 持つもの |
| - | - |
| 活動 | id / タイトル / きっかけ（話す・見本・今日のお題・作品・予定表・作る）/ 意図（本人の言葉。空でよい。直せる・外せる）/ 作業対象（§6-2 の 3 種。複数持てる: 見本 + 写真 など）/ 変化の列 / この活動の会話 / 状態（作業中・一区切り・今日はここまで・やめた）/ 止まった場所（最後の変化 + 「次にすること」1 行） |

戻すのも新しい「変化」（「10:40 のところに戻した」）。履歴は消えない（v1.0 303行）。

## 4. 状態遷移

```
作るの入口 ─見本を動かす / 案を選ぶ / 写真 / リンク / 思いつき─▶ 作業中
作業中 ─試す（本人）/ 任せる（バディが作る・直す・引き受ける）/ 人が手伝った─▶ 作業中（変化 +1、結果つき）
作業中 ─前に戻す / ここに戻す─▶ 作業中（変化 +1「…のところに戻した」）
作業中 ─違う（バディの変化に）─▶ 戻して、相談列に「どこが違う？」の候補 5 つ + 1 行
作業中 ─作品に残す─▶ 作業中のまま（作品 +1。活動は閉じない）
作業中 ─今日はここまで ▸ 続きがある─▶ 今日はここまで（止まった場所 + 次にすること。続きをする に出る）
作業中 ─今日はここまで ▸ ここで一区切り─▶ 一区切り（制作中一覧から外れ、あしあとに残る。「作品に残す？」を 1 回だけ添える。残さなくてよい）
作業中 ─この活動をやめる（…）─▶ やめた（あしあとから「もう一度やる」）
作品 ─続きを作る─▶ 作業中（同じ活動）
```

- **アイデアを練る**は独立画面にしない。意図があればバディの仮の案を比べることが、無ければ見本を 1 か所変えることが「練る」（v1.0 290行「アイデア検討が長引いたら試作へ進める」の前倒し）。言葉で練るのは相談列。
- **比べる**: 変化の列の「比べる」で 2 つを選ぶ → 作業対象の上に 2 枚並ぶ。候補状態（案 2〜3 個）は最初から並んでいる。
- **保存と公開の分離**: 作るには「作品に残す」しかない。「見せる相手を選ぶ」は作品画面（引き継ぎ 143行）。
- **中断**: 「今日はここまで」で保存するのは最後の変化・相談列の最後の 1 往復・「次にすること」1 行（既定はバディ案。本人が直す／空にする）。長いアンケートは出さない（v1.0 339行）。
- **やめる**は消さない（削除の運用は v1.0 878行の未決）。
- **違う**: バディの変化の行と、相談列の返事の 2 か所。押すと戻して、候補（形・大きさ・材料／色・動き・それ以外）+ 1 行（引き継ぎ 155行「候補を選ぶ、見本を指す」）。

## 6. 要素と理由

### 6-1 作るの入口

| 要素 | 理由 |
| - | - |
| 制作中の行（タイトル・最後の変化・次にすること・続きを作る） | 再開に要るのは「何を・どこまで・次に何を」（v1.0 238行） |
| 見本 3 枚 + 動かしてみる | 意図が無くても始められる入口。名前が結果を予告（引き継ぎ 101行） |
| 変えられるところ 2 語 | 触ったら何が起きるかの予告。説明文の代わり |
| 別の見本を見る | 見るだけで流れ続けない（v1.0 315行）。3 枚ずつ |
| 思いつき 1 行 + 写真・リンク | 言葉・実物・外部ツールの入口。最後に置く |
| 今日のお題を見る | 既知の外への入口。カードは重複表示しない |

出さない: 工場の型名・検証状態・変奏の分類（v1.0 92行）。カテゴリ一覧（予定表の「今まで取り組んできたこと」と重複）。

### 6-2 作業対象（3 種。1 つの活動に複数置ける）

| 種 | 中身（例） | 見え方 | 本人が変える | バディに任せると |
| - | - | - | - | - |
| **動かせる見本**（工場の型 2・4） | 回路のシミュレーション / Python ゲームの見本コード / マイクラのコマンド例（`docs/content-factory-design.md` §5 の例） | 線画の描画 or コード/コマンドの短い表示 + 「試す」 | 素材の「本人が変えられる箇所」（v1.0 620行）を 2〜3 個のスライダー/選択肢/短い入力で | 1 手を代わりに変える、または「こうしたい」に合わせて値を探す |
| **バディが作った試作**（AI 生成物） | ドアストッパーの 3D 形状 / 絵 / 文章 / 小さなゲーム。モックではプレビュー = 線画 SVG かテキスト | プレビュー + 「変えられるところ」+ 「試す」（動くものは再生、文章は読む） | 変えられるところを触る、または言葉で頼む | 作る・作り直す・案を 2〜3 個出す・一部だけ直す（v1.0 427行「見本、図、コード、試作を出して、反応から直す」） |

候補状態（案 2〜3 個）は「バディが作った試作」が複数並んでいる状態。1 つを「これにする」で選ぶと通常の作業対象になり、他は変化の列に「見送った案」として残る。

### 6-3 外部で作る時に作業台が助けること（一文）

**外で作る時の作業台は、「今の一歩と次の一歩」「見本・レシピ・バディの計算結果を手元に置くこと」「前と今を並べて違いを言葉にすること」「残すか続けるかの区切り」を持つ場所で、スクショの保管庫ではない。** 話すとの違いは、同じ活動の見本・試作・写真・変化が一画面にあり、相談がそれを指して進むこと（v1.0 333行「意図や選んだ素材を説明し直す必要はありません」）。

### 6-4 「バディに任せる」の中身（対象別）

押すと相談列に「何を任せる？」の候補が対象に応じて出る（毎回モード選択ではなく、押した時だけ）:
- 見本: 「この値を探して」「1 か所変えて」
- 試作: 「作り直して」「別の案を 2 つ」「ここだけ直して」
- 外部・実物: 「寸法を計算して」「手順を整理して」「コマンドを作って」
+ 常に「言葉で頼む」（composer へ）。バディが行った分は変化の列に琥珀の印で積まれ、行に「違う」。

### 6-5 区切りの操作（2 つ）

| 操作 | 押した結果 |
| - | - |
| 作品に残す | ダイアログ（§6-7）。活動は閉じない |
| 今日はここまで | 小さなダイアログ: 「次にすること」1 行（既定はバディ案・直せる・空にできる）+ 選択「続きがある」（既定）/「ここで一区切り」→ `#paused`（`paused_p` を作る用の文に）。一区切りの時だけ、`#paused` に「作品に残す？」ボタンを 1 つ添える（残さなくてよい） |

「できた」は廃止（§0-1 #4）。バディの受け止め（「羽を広げたら、さっきよりゆっくり落ちたね」）は「試す」の結果が出た時に返すので、宣言ボタンは要らない。

### 6-6 ここまでの変化（列）

- **積まれる瞬間は 4 つだけ**: (1)「試す」を押した (2) バディが試作・値を置いた (3) 写真・スクショを足した (4) 戻した。スライダーのドラッグや入力中は積まれず、作業対象の右上に薄い印「まだ試していない」。「前に戻す」は直前に積まれたものへ。
- 行 = 時刻 / 誰が（出所チップ: 本人 = 青 `.src-own`、バディ = 琥珀 `.src-ai`、人 = 緑 `.src-record` + 名前。R-10 流用）/ 何を変えた / 結果。操作は「ここに戻す」だけ常時、バディ行だけ「違う」も。
- 既定は最新 2 行 + 「ぜんぶ見る（n）」。見出し右に「比べる」（2 行を選んで並べる）。
- 「版」の語は出さない。指す時は時刻（「10:40 のところ」）。

### 6-7 「作品に残す」ダイアログ

| 項目 | 必須 | 理由 |
| - | - | - |
| 残すところ（既定: 今。変化の列から時刻で選び直せる） | 既定あり | 試作も残せる（v1.0 367行） |
| タイトル（既定: 活動名） | 既定あり | 作品一覧の見出し |
| 気に入っているところ（1 行） | 任意 | 本人の言葉。空で残せる |
| 誰が何をした（自動。「本人 3 回 · バディ 2 回 · 田中さん 1 回」+ 各 1 行） | 表示のみ | 誇張しない記録（v1.0 371行）。編集不可、本人の言葉と混ぜない |
| ボタン「作品に残す」「やめる」 | | 共有の項目は置かない |

残した後: トースト「作品に残した」+「作品で見る」。

## 8. シナリオで通し検証

### A. 紙の羽（代表例 7、v1.0 1121〜1135行）— 見本 → 実物写真を同じ活動で
1. 左ナビ「作る」→ 制作中なし → 見本 3 枚。（題材は §11 Q2 で決める。ここでは v1.0 の例に従い紙の羽で書く）「動かしてみる」。
2. 作業台: 今の一歩「今: 幅を変えてみる」。見本 + スライダー「幅」「角度」+「試す」。相談「まず動かしてみる？…」。
3. 幅 20→34 とドラッグ → 「まだ試していない」。「試す」→ 結果「落ちるまで 1.2 秒 → 1.8 秒」。変化 +1（本人）。バディ「羽を広げたら…」。
4. 相談「もっと回るのにしたい」→ バディ「角度を変えると回り方が変わるよ」+「やってみる」「説明を聞く」。
5. 実物: 入力欄横「写真を見せる」→ 作業対象に写真が足される（見本の下）。「何を変えた？」→「形」+「切る線を長くした」。変化 +1（本人 + 人〈田中さん〉）。結果は本人の 1 行「ゆっくりになった」。
6. 「作品に残す」→ 残すところ = 今、タイトル「ゆっくり落ちる紙の羽」、誰が何をした「本人 2 回 · 田中さん 1 回」。
7. 翌日、作品「続きを作る」→ 同じ活動。

### B. ドアストッパー（代表例 4 / 25、v1.0 495行・1093〜1099行）— 話すから、仮の案、任せる、外部 3D
1. 話す「ドアが閉まらないようにしたい。形は AI に作ってほしい」→ bridge → 作業台。引用枠（本人の言葉）+「直す」「外す」。作業台の最初 = **仮の案 3 つ**（くさび / L 字 / 重り付き。バディが作った試作のプレビュー）。バディ「使う場所や大きさを、サポーターと確かめよう。近い案を選ぶか、違うところを教えて」。
2. 本人が「くさび」を「これにする」→ 作業対象に。他 2 案は変化の列に「見送った案」。変えられるところ「高さ・幅・すべり止め」。
3. 高さ 20→25、「試す」（プレビューが動く）→ 変化 +1（本人）。
4. 「バディに任せる」→ 候補「作り直して / 別の案を 2 つ / ここだけ直して」→「ここだけ直して」+ 言葉「すべり止めの溝を入れて」→ 変化 +1（バディ）。行に「違う」。
5. 3D プリントは外部: 「リンクを貼る」→ 作業対象 3 つ目（外部の記録）。田中さんが出力 → 「写真を足す」（人）。結果「ドアが止まった」。
6. 「作品に残す」→ 誰が何をした「バディ 2 回（案 3 つ・溝）· 本人 2 回 · 田中さん 1 回」。任せたことが参加として残り、本人の技能に付け替えない。

### C. マイクラ建築（予定表から、外部ツール、中断・再開）
1. 今日の予定 p1「建築（大きく）」の「…」→「作るで開く」→ 制作中にある → 作業台。作業対象 = 外部の記録（Minecraft + 前回のスクショ 2 枚）。今の一歩「今: 塔を 2 倍に → 次: 屋根を決める」。
2. 「スクショを足す」→「何を変えた？」→「大きさ」+「塔を 2 倍に」→ 変化 +1。バディ「前の写真と並べて見る？」→「比べる」で 2 枚。
3. 「バディに任せる」→「コマンドを作って」+「屋根を円すいに」→ 相談列にコマンド + 作業対象に「バディが作った試作」（コマンド例）が足される（琥珀）。
4. 10:50 サークル対話 → 「今日はここまで」→ 次にすること（既定「屋根を決める」→ 本人が「窓を増やす」に直す）/「続きがある」→ `#paused`。
5. 11:10「続きをする」→ 作業台。相談列の先頭に止まった場所 + 次にすること。
6. ここで作業台が助けたこと（§6-3 の一文の検証）: 一歩の見通し / バディのコマンドが手元に残る / 前と今の比較 / 区切り。話すだけならコマンドは会話に流れて消える。

## 9. 「本人が選んだ・変えたこと」と結果、AI／人の記録

- 変化の 1 行が最小単位: 誰が / 何を変えた / 結果。結果は確かめられたことだけ。確かめていなければ「まだ確かめていない」で、バディは褒めない（v1.0 457行）。
- 出所は既存 3 種（R-10）を流用: 本人 = 青、バディ = 琥珀、人 = 緑 + 名前。
- 返事は「受け止める → 確認できた変化 → 次の余地」。評価語は禁止語のまま（CONTRACT §I）。
- 作品の「誰が何をした」は自動・編集不可。本人の言葉は別欄。
- 自己理解への問い: 「ここで一区切り」の後に 1 回だけ、答えなくてよい形で相談列に（v1.0 409行型）。§12 で設計者推奨として進める。
