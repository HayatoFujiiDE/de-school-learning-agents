## 1. 一文と範囲

**利用者がしたいこと**: まだ何を作るか決まっていなくても、見本や写真を触るところから始めて、変えた結果を確かめながら形にし、残したいものを作品にする。

| 担う | 担わない（どこが担うか） |
| - | - |
| アイデアを練る・比べる・試作する・制作する（AI／人と分担）・作品に残す・残した後の再編集 | 日常会話・相談の起点（**話す**。作るの中の相談は「この活動についての相談」に限る） |
| 制作中の活動の一覧と再開 | 完成品を眺める・他の人に見せる・公開する（**作品**。保存と公開は別操作: 引き継ぎ 143行） |
| 変えたこと→結果、AI／人が担った部分の記録 | 過去の発見や会話をたどる（**あしあと**）、止まった場所へ戻る共通導線（**続きをする**） |

## 2. 概念（画面の裏にある最小の単位）

［事実］v1.0「実装へ引き継ぐ最小の情報構造」702〜719行: 活動は「出会いのきっかけ、開始時の希望、途中で育った意図、試作、本人の選択・変更・委任、環境や支援、結果と手応え、現在の状態、止まった場所、作品、次の候補」を持ち、「作る」と「続きをする」は同じ活動へ戻る。作品は「作品本体、元の制作活動、保存・完成の状態、版、本人の工夫や判断、AI や人との分担」を持つ。

［提案］モックで持つ最小の形:

| 単位 | 持つもの |
| - | - |
| 活動 `activity` | id / タイトル（本人の言葉か見本名） / きっかけ `origin`（話す・見本・今日のお題・作品・予定表・作るで直接）/ 意図（本人の言葉。空でよい）/ 作業対象 `subject`（§6-2 の 3 種のどれか 1 つ）/ 版の列 `versions[]` / この活動の会話 `thread[]` / 状態（作業中・区切り・今日はここまで・やめた）/ 止まった場所（最後の版 + 本人が直せる 1 行） |
| 版 `version` | 何を変えたか（例「羽の幅 20 → 34」）/ 誰が（本人・バディに任せた・人〈サポーター・友達〉）/ 結果（確かめられた変化。未確認なら「まだ確かめていない」）/ 時刻 |
| 作品 `work` | 活動 id / 残した版 id / タイトル / 本人の言葉（気に入っているところ。任意）/ 分担の要約（版から自動。編集不可） |

「版」は巻き戻し単位であり、**戻すのも新しい版**（「版 3 に戻した」）。履歴を消さない（v1.0 303行「経緯を消したり…最初からやり直させたりしません」）。

## 4. 状態遷移

```
作るの入口 ──見本を動かす / 写真 / リンク / 思いつき──▶ 作業中（版 0）
作業中 ──変える（本人）/ 任せる（バディ）/ 人が手伝った──▶ 作業中（版 n+1、結果つき）
作業中 ──前に戻す──▶ 作業中（版 n+1 =「版 k に戻した」）
作業中 ──違う（バディの変更に対して）──▶ その版を戻し、相談列にどこが違うかを 1 行
作業中 ──作品に残す──▶ 作業中のまま（作品に 1 件増える。活動は閉じない）
作業中 ──できた（区切り）──▶ 区切り（作品に残すを促す 1 行。残さなくてよい）
作業中 ──今日はここまで──▶ 今日はここまで（止まった場所を保存。続きをする に出る）
作業中 ──この活動をやめる──▶ やめた（制作中一覧から消える。あしあとに残る。「もう一度やる」で作業中へ）
作品 ──続きを作る──▶ 作業中（同じ活動）
```

- **アイデアを練る**は独立した画面にしない（［提案］）。見本を 1 か所変えること・比べることがそのまま「練る」であり、v1.0 290行「アイデア検討が長引いたら試作へ進める入口を出します」の裏返しで、最初から試作の中にいる。相談列で言葉で練ることもできる。
- **比べる**は版の並置（§6-2「ここまでの変化」で 2 つの版を選ぶ→作業対象の上に 2 枚並ぶ）。見本同士の比較は入口で「別の見本を見る」。
- **保存と公開の分離**: 作るには「作品に残す」しかない。「見せる相手を選ぶ」は作品画面。残す時のダイアログに共有の項目を置かない（引き継ぎ 143行）。
- **中断と再開**: 「今日はここまで」で保存するのは (a) 最後の版 (b) 相談列の最後の 1 往復 (c) 本人が直せる「次にすること」1 行（既定はバディが書いた候補。空にもできる）。長いアンケートは出さない（v1.0 339行）。
- **やめる**は消さない。「やめた」活動はあしあとから戻れる。削除は本書の範囲外（保存・削除の運用は v1.0 878行の未決）。
- **違うと伝える**は 2 か所: バディが置いた版の行に「違う」／相談列の返事に「違う」。押すと版を戻し、相談列に「どこが違う？」ではなく **本人が指せる選択肢**（「形」「大きさ」「色」「動き」「それ以外」）＋自由入力を出す（引き継ぎ 155行「候補を選ぶ、見本を指す」）。
- **任せる**は版 1 つ分の操作。「全部任せる」は相談列で言葉で頼む → バディが数版まとめて積み、各版に「バディ」の印。本人はその後で「残す／戻す／違う」で関わる（v1.0 459行「最初は実演を見たり任せたりしてもよく」）。

## 5. レイアウト

幅の段は CONTRACT §B の 4 段（≥1121 / 951〜1120 / 701〜950 / ≤700）をそのまま使う。

### 5-1 作るの入口（`#make`）

1 列、`max-width: 900px`（話すの 820 より広く、作業台と同じ幅感）。上から:

1. 見出し `h1`「作る」＋ 1 行の補助（js「見本を動かすところから始められる」）。ポエムではなく操作の予告。
2. **制作中**（活動が 1 件以上の時だけ）: 行リスト。各行 = タイトル ／ 最後の変化（「羽の幅 20 → 34 · 11/2 10:40」）／ 止まった場所の 1 行 ／ 右端ボタン「続きを作る」。行は `.project-row` 相当（codex）。
3. **見本から始める**: 3 枚（v1.0 309行の「三案程度」に揃える。配分: いつもの好きに近い 1・隣 1・普段出会わない 1、v1.0 311行。モックは決定論で 3 件固定）。各枚 = 見本の絵（線画 SVG、題材固有の図版は作らない: CONTRACT §A）／ 名前 ／「変えられるところ」を 2 語（例「幅・角度」）／ ボタン 1 つ「動かしてみる」。下に小リンク「別の見本を見る」（次の 3 枚）。
4. **写真・リンクから**: 「写真を見せる」「リンクを貼る」の 2 ボタン（教室の実物、Minecraft、外部ツール）。
5. **思いつきから**: 1 行の入力欄 + 「作るを始める」。**最後に置く**（入力を参加条件にしない: v1.0 383行）。
6. 下端に小リンク「今日のお題を見る」（未知への入口を残す: 引き継ぎ 171行）。

≤700 は同じ縦順。見本 3 枚は横スクロールでなく縦 3 段（横スクロール禁止: CONTRACT §I）。

### 5-2 作業台（`#make/<activityId>`）

| 幅 | 構成 |
| - | - |
| ≥1121 | `.content` 内 `.make-layout` = grid `minmax(0,1fr) 360px`、gap 28px。左 **作業台**（主役）、右 **相談**（`aside.talk-side`、sticky top 96px、内部スクロール。今日の予定パネルと同じ寸法・同じ開閉作法）。相談を閉じると作業台が `max-width: 900px` で中央に |
| 951〜1120 | 相談 300px、gap 20px |

［事実］v1.0 335行「パソコンでは会話と対象を並べる案、スマートフォンでは対象と会話を必要に応じて切り替える案」。［提案］相談を**右**に置く理由: 話す画面で右が「開閉できる補助パネル」になっている（CONTRACT §B）ため、作るでも「主役は中央左、補助は右で開閉」の作法を揃える。Codex 版は会話が左（0.8fr）だが、作るの主役は作業対象なので主役を読み順の先頭に置く。→ 未決 §11-5。

**今日の予定パネルとの共存**: 作業台では右列を相談に使うため、topbar の「今日の予定」は全幅で **drawer（≤950 の形）として被せる**。［事実］現行は R-8「スコープ外ルート・#paused = パネルなし・plan-toggle は #talk へ戻して開く」。［提案］`#make` ではこれを drawer に変える（作業中に予定を見たいのに話すへ飛ばされると作業台が見えなくなる）。予定の編集機能は同じ部品なので増えない。

**作業台の中（上から）**:

1. **活動の見出し行**: タイトル（本人の言葉か見本名。クリックで 1 行編集）／ きっかけチップ（「話すから」「見本から」「今日のお題から」「作品から」）／ 右端「…」（この活動をやめる・タイトルを直す）。
2. **作業対象**（§6-2）: 見本なら描画 + 「変えられるところ」の操作。写真なら写真の並び + 「写真を足す」。リンクなら外部ツール名 + リンク + スクショ。
3. **試す・確かめる行**: 「試す」（見本を動かす／再生）と結果の 1 行（「落ちるまで 1.8 秒」）。
4. **操作行（主な操作 ≤ 5）**: 「前に戻す」／「バディに任せる」／「できた」／「作品に残す」／「今日はここまで」。
5. **ここまでの変化**（版の列。折りたたみ可、既定は開く）: 1 行 = 時刻 ／ 誰が（出所チップ: 本人＝青 `.src-own`、バディ＝琥珀 `.src-ai`、人＝緑 `.src-record` を流用、R-10）／ 何を変えた ／ 結果 ／ 行の操作「ここに戻す」「比べる」。バディの版だけ「違う」も出る。

**相談列の中**: 活動の `thread` だけ（話す全体の履歴は混ぜない。先頭に「話すから持ってきた」引用があれば本人の言葉チップで 1 件）。バディの返事は v1.0 453行の形「本人の関与を受け止める → 確認できた変化を返す → 次に関われる余地」。返事の下に必要な時だけ 2〜3 個のボタン（「やってみる」「説明を聞く」「あとで」。v1.0 252行）。composer は話すと同じ部品（写真・音声の体験例・送る）。「違う」は返事ごとに `.btn.ghost.small`。

## 6. 要素一覧と理由

### 6-1 作るの入口

| 要素 | 理由（理解 or 操作） |
| - | - |
| 制作中の行（タイトル・最後の変化・止まった 1 行・続きを作る） | 再開に要るのは「何をしたかったか・どこまで・次に何を」（v1.0 238行）。会話全文は要らない |
| 見本 3 枚 + 「動かしてみる」 | 意図が無くても始められる唯一の入口。ボタン名が結果を予告する（引き継ぎ 101行「見本を動かしてみる」） |
| 「変えられるところ」2 語 | 触ったら何が起きるかの予告。説明文を置かずに済む |
| 「別の見本を見る」 | 見るだけで流れ続けない（v1.0 315行）ため 3 枚ずつ、ページ送りでなくリンク 1 つ |
| 写真を見せる／リンクを貼る | 実物工作・Minecraft・外部ツールを同じ活動につなぐ（v1.0 299行） |
| 思いつき 1 行 | 言葉がある子の入口。最後に置くことで「まず書け」にしない |
| 今日のお題を見る | 既知の好みの外への入口（引き継ぎ 171行）。カードを重複表示せずリンクだけ |

出さないもの: 工場の型名・検証状態・変奏の内部分類（v1.0 92行「ファクトリーの工程や教育理論の分類は並べません」）。カテゴリの一覧（予定表の「今まで取り組んできたこと」と重複する）。

### 6-2 作業対象（3 種）

| 種 | 見え方 | 変える操作 | 結果の出所 |
| - | - | - | - |
| 動かせる見本（工場の型 2・4。`docs/content-factory-design.md` §5） | 線画の描画 + 「試す」 | 素材の「本人が変えられる箇所」（v1.0 620行「関わり始める入口」）をスライダー／選択肢で 2〜3 個。1 操作 = 1 版 | 見本が返す値（モックは決定論の計算） |
| 写真（実物工作・教室） | 写真を時系列に並べる。最新が大きい | 「写真を足す」+ 「何を変えた？」を候補（形・大きさ・材料・つけ方・それ以外）か 1 行で | 本人が書く 1 行か「まだ確かめていない」 |
| リンク・ファイル（Minecraft・Blockbench・Scratch 等） | ツール名 + リンク + スクショ（任意） | 「スクショを足す」+ 同上 | 同上 |

写真・リンクでは結果を機械で確かめられない。バディは「写真から断定しない」（v1.0 696行）ので、返事は「変えたと書いたこと」を受け止める形に限る。

### 6-3 作業台の操作行（5 つ）

| 操作 | 押した結果 |
| - | - |
| 前に戻す | 直前の版へ。版の列に「版 n に戻した」が増える。5 秒トーストの「戻す」で取り消せる（既存 R-6 と同じ作法） |
| バディに任せる | バディが 1 手だけ変えた版を積み、相談列に「{何を}を{こう}変えたよ。見て、残すか戻すか決めて」。行に「違う」 |
| できた | 状態を「区切り」に。相談列にバディの受け止め 1 文（「羽を広げたら、さっきよりゆっくり落ちたね」の型）+ 「作品に残す？」ボタン 1 つ。残さなくてよい |
| 作品に残す | ダイアログ（§6-4） |
| 今日はここまで | 止まった場所の 1 行（既定文を本人が直せる）→ `#paused`（既存画面。`paused_p` の文は作る用に差し替え） |

「違う」「やめる」は操作行に入れない（違う＝版の行・返事の行、やめる＝「…」）。5 つを超えない。

### 6-4 「作品に残す」ダイアログ

| 項目 | 必須 | 理由 |
| - | - | - |
| 残す版（既定: 今の版。版の列から選び直せる） | 必須（既定あり） | 試作を残す場合がある（v1.0 367行「本人が残した試作」） |

| 気に入っているところ（1 行） | 任意 | 本人の言葉。空のまま残せる |

## 8. シナリオで通し検証

### A. 紙の羽（代表例 7、v1.0 1121〜1135行）— 見本 → 実物 → 写真で同じ活動

1. 左ナビ「作る」。制作中なし → 見本 3 枚が先頭。「紙の羽（回って落ちる）」の「動かしてみる」。
2. 作業台: 線画の羽 + 「幅」「角度」のスライダー + 「試す」。相談列にバディ「まず動かしてみる？…」。活動が `origin: 見本` で生成、版 0。
3. 本人が幅 20→34、「試す」→ 結果「落ちるまで 1.2 秒 → 1.8 秒」。版 1（本人）。バディ「羽を広げたら、さっきよりゆっくり落ちたね…」。
4. 本人「もっと回るのにしたい」（相談列）→ バディ「角度を変えると回り方が変わるよ。試す？」+ ボタン「やってみる」「説明を聞く」。
5. 「実物で試す」: 「写真を見せる」→ 作業対象に写真が**追加**される（見本と写真が同じ活動にある。見本は上、写真は下）。「何を変えた？」→「形」+ 1 行「切る線を長くした」。版 2（本人・人〈田中さん が切るのを手伝った〉）。結果は本人が書く「ゆっくりになった」。
6. 「できた」→ 区切り。「作品に残す」→ 残す版 = 版 2、タイトル「ゆっくり落ちる紙の羽」、分担「本人 2 回 · 田中さん 1 回」。
7. 翌日、作品「続きを作る」→ 同じ活動の版 2 から。

確認: 話す → 作る → 試作変更 → 作品 → 再編集（引き継ぎ 137行）が一本。本人が選んだこと（幅・形）と結果（秒数・本人の記述）が版ごとに対。手伝いは「人」の印で残る。

### B. ドアストッパー（代表例 4 / 25、v1.0 495行・1093〜1099行）— 話すから、任せる、外部の 3D

1. 話す: 「ドアが閉まらないようにしたい。形は AI に作ってほしい」→ bridge → 作業台。相談列の先頭に本人の言葉（青）で引用。作業対象は未選択（見本／写真／リンク）。バディ「使う場所や大きさを、サポーターと確かめよう。まず案を見て、使えそうか決められるよ」+「案を見る」。
2. 「バディに任せる」→ バディが「くさび形」の見本を作業対象に置き（版 1・バディ）、「変えられるところ: 高さ・幅・すべり止め」。相談列「3 つ案があるよ。比べる？」→「比べる」で版を 2 枚並べる（版 1〜3、全部バディ）。
3. 本人が版 2 を「ここに戻す」= 選ぶ（版 4・本人「版 2 を選んだ」）。高さだけ 20→25（版 5・本人）。
4. 3D プリントは外部: 「リンクを貼る」で Blockbench/プリンタのファイルリンク（版 6・人〈田中さん が出力〉）。写真を足す（版 7・本人「置いてみた」）。結果「ドアが止まった」。
5. 「作品に残す」: 分担「バディ 3 回 · 本人 3 回 · 田中さん 1 回」。本人の技能として誇張されない。任せたことも参加として残る。

確認: 任せる → 本人が関わり直す（v1.0 459行）。「AI/人が担った部分」が版の印で一目で分かる。

### C. マイクラ建築（予定表の行から、外部ツール、中断・再開）

1. 今日の予定の p1「建築（大きく）」の「…」→「作るで開く」。制作中に「建築（大きく）」があれば作業台、無ければ作るの入口（マイクラの見本が先頭）。ここでは既存あり → 作業台。

## 9. 「本人が選んだ・変えたこと」と結果、AI／人の記録

- 版の 1 行が記録の最小単位: **誰が／何を変えた／結果**。結果は「確かめられたこと」だけ（見本の値、本人の記述、写真）。確かめていない版は「まだ確かめていない」で、バディは褒めない（v1.0 457行「変化の原因が確かでなければ断定せず」）。
- 誰が: 本人（青 `.src-own`）／ バディ（琥珀 `.src-ai`）／ 人（緑 `.src-record`。名前つき: 田中さん・友達）。既存の出所 3 種（R-10）を流用し新色を作らない。
- バディの返事は「本人の関与を受け止める → 確認できた変化 → 次の余地」。評価語（点数・上手・成長 等）は禁止語のまま（CONTRACT §I）。
- 作品に残す時の分担要約は版から自動で作り、編集できない。本人の言葉（気に入っているところ）は別欄。
- 自己理解への橋: 作るでは出さない。「できた」の後に v1.0 409行型の問い（「形を少しずつ変えるの、面白かった？」）を**相談列に 1 回だけ**、答えなくてよい形で置く案。未決 §11-10。
