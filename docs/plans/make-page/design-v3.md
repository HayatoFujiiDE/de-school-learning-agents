## 4. 状態遷移

```
作るの入口 ─見本を動かす / 案を選ぶ / 写真 / リンク / 思いつき─▶ 作業中
作業中 ─試す（本人）/ 任せる（バディが作る・直す・引き受ける）/ 人が手伝った─▶ 作業中（変化 +1、結果つき）
作業中 ─前に戻す / ここに戻す─▶ 作業中（変化 +1「…のところに戻した」）
作業中 ─違う（バディの変化に）─▶ 戻して、相談列に「どこが違う？」の候補 5 つ + 1 行
作業中 ─作品に残す─▶ 作業中のまま（作品 +1。活動は閉じない）
作業中 ─今日はここまで ▸ 続きがある─▶ 今日はここまで（止まった場所 + 次にすること。続きをする に出る）
作業中 ─今日はここまで ▸ ここで一区切り─▶ 一区切り（制作中一覧から外れ、あしあとに残る。「作品に残す？」を 1 回だけ添える。残さなくてよい）
作業中 ─この活動をやめる（…）─▶ やめた（あしあとから「もう一度やる」）
  ※ 上の 3 つの「区切る・やめる」の瞬間に、バディは状況を見て「背中を押す」か「受け止める」かを選ぶ（§6-8）。
    押しても最終決定は本人。押した結果「やっぱり続ける」なら作業中に戻る（変化は積まれない）。
作品 ─続きを作る─▶ 作業中（同じ活動）
```

- **アイデアを練る**は独立画面にしない。意図があればバディの仮の案を比べることが、無ければ見本を 1 か所変えることが「練る」（v1.0 290行「アイデア検討が長引いたら試作へ進める」の前倒し）。言葉で練るのは相談列。
- **比べる**: 変化の列の「比べる」で 2 つを選ぶ → 作業対象の上に 2 枚並ぶ。候補状態（案 2〜3 個）は最初から並んでいる。
- **保存と公開の分離**: 作るには「作品に残す」しかない。「見せる相手を選ぶ」は作品画面（引き継ぎ 143行）。
- **中断**: 「今日はここまで」で保存するのは最後の変化・相談列の最後の 1 往復・「次にすること」1 行（既定はバディ案。本人が直す／空にする）。長いアンケートは出さない（v1.0 339行）。
- **やめる**は消さない（削除の運用は v1.0 878行の未決）。
- **違う**: バディの変化の行と、相談列の返事の 2 か所。押すと戻して、候補（形・大きさ・材料／色・動き・それ以外）+ 1 行（引き継ぎ 155行「候補を選ぶ、見本を指す」）。

7. **区切りの操作**（右寄せ 2 つ・線で上と区切る）: 「作品に残す」「今日はここまで」。

折り目の上で同時に見える操作は 試す / 前に戻す / バディに任せる / 作品に残す / 今日はここまで の 5 つ（CONTRACT §I の数え方）。

**相談列**: この活動の会話だけ。先頭に引用枠（あれば）。バディの返事は「本人の関与を受け止める → 確認できた変化 → 次に関われる余地」（v1.0 453行）。必要な時だけ 2〜3 ボタン（やってみる / 説明を聞く / あとで: v1.0 252行）。返事ごとに `.btn.ghost.small`「違う」。composer は話すと同じ部品。

## 6. 要素と理由

### 6-1 作るの入口

| 要素 | 理由 |
| - | - |
| 制作中の行（タイトル・最後の変化・次にすること・続きを作る） | 再開に要るのは「何を・どこまで・次に何を」（v1.0 238行） |
| 見本 3 枚 + 動かしてみる | 意図が無くても始められる入口。名前が結果を予告（引き継ぎ 101行） |
| 変えられるところ 2 語 | 触ったら何が起きるかの予告。説明文の代わり |
| 別の見本を見る | 見るだけで流れ続けない（v1.0 315行）。3 枚ずつ |
| 思いつき 1 行 + 写真・リンク | 言葉・実物・外部ツールの入口。最後に置く |
| 今日のお題を見る | 既知の外への入口。カードは重複表示しない |

出さない: 工場の型名・検証状態・変奏の分類（v1.0 92行）。カテゴリ一覧（予定表の「今まで取り組んできたこと」と重複）。

### 6-2 作業対象（3 種。1 つの活動に複数置ける）

| 種 | 中身（例） | 見え方 | 本人が変える | バディに任せると |
| - | - | - | - | - |
| **動かせる見本**（工場の型 2・4） | 回路のシミュレーション / Python ゲームの見本コード / マイクラのコマンド例（`docs/content-factory-design.md` §5 の例） | 線画の描画 or コード/コマンドの短い表示 + 「試す」 | 素材の「本人が変えられる箇所」（v1.0 620行）を 2〜3 個のスライダー/選択肢/短い入力で | 1 手を代わりに変える、または「こうしたい」に合わせて値を探す |
| **バディが作った試作**（AI 生成物。確定 Q3: 丸ごと作ってよい） | ドアストッパーの 3D 形状 / 絵 / 文章 / 小さなゲーム / コマンド列。モックではプレビュー = 線画 SVG かテキスト | プレビュー + 「変えられるところ」+ 「試す」（動くものは再生、文章・コマンドは読む） | 変えられるところを触る、「これにする」で選ぶ、「違う」で戻す、または言葉で頼む | 作る・作り直す・案を 2〜3 個出す・一部だけ直す（v1.0 427行「見本、図、コード、試作を出して、反応から直す」）。作ったものは変化の列に琥珀「バディ」で残る |
| **外部・実物の記録**（Minecraft / Scratch / 工作 / 3D プリント） | ツール名 + リンク + スクショ・写真の列 | 最新が大きく、前のものが小さく並ぶ + 「写真を足す」「スクショを足す」 | 外で作り、写真・スクショを足すたびに「何を変えた？」候補 5 つ + 1 行（任意。確定 Q5） | 計算・寸法・手順の整形・コマンド生成など「引き受ける」作業（v1.0 428行）。結果は相談列に + 必要なら「バディが作った試作」として作業対象に足す |

候補状態（案 2〜3 個）は棚（§6-9）に案が並び、作業対象が空枠の状態。棚の 1 つを「これにする」で取り込むと「バディが作った試作」が作業対象になり、他は棚の「見送った案」に残る。

### 6-3 外部で作る時に作業台が助けること（一文）

**外で作る時の作業台は、「今の一歩と次の一歩」「見本・レシピ・バディの計算結果を手元に置くこと」「前と今を並べて違いを言葉にすること」「残すか続けるかの区切り」を持つ場所で、スクショの保管庫ではない。** 話すとの違いは、同じ活動の見本・試作・写真・変化が一画面にあり、相談がそれを指して進むこと（v1.0 333行「意図や選んだ素材を説明し直す必要はありません」）。

### 6-4 「バディに任せる」の中身（対象別）

押すと相談列に「何を任せる？」の候補が対象に応じて出る（毎回モード選択ではなく、押した時だけ）:
- 見本: 「この値を探して」「1 か所変えて」
- 試作: 「作り直して」「別の案を 2 つ」「ここだけ直して」
- 外部・実物: 「寸法を計算して」「手順を整理して」「コマンドを作って」
+ 常に「言葉で頼む」（composer へ）。バディが行った分は変化の列に琥珀の印で積まれ、行に「違う」。

### 6-5 区切りの操作（2 つ）

| 操作 | 押した結果 |
| - | - |
| 作品に残す | ダイアログ（§6-7）。活動は閉じない |
| 今日はここまで | 小さなダイアログ: 「次にすること」1 行（既定はバディ案・直せる・空にできる）+ 選択「続きがある」（既定）/「ここで一区切り」。ダイアログの上部にバディの一言（§6-8 の 3 通りのどれか。押さない時は受け止めの 1 文だけ）→ `#paused`（`paused_p` を作る用の文に）。一区切りの時だけ、`#paused` に「作品に残す？」ボタンを 1 つ添える（残さなくてよい） |

「できた」は廃止（§0-1 #4）。バディの受け止め（「羽を広げたら、さっきよりゆっくり落ちたね」）は「試す」の結果が出た時に返すので、宣言ボタンは要らない。区切る・やめるの最終決定は本人（確定 Q4）。

### 6-6 ここまでの変化（列）

- **積まれる瞬間は 4 つだけ**: (1)「試す」を押した (2) バディが試作・値を置いた (3) 写真・スクショを足した (4) 戻した。スライダーのドラッグや入力中は積まれず、作業対象の右上に薄い印「まだ試していない」。「前に戻す」は直前に積まれたものへ。
- 行 = 時刻 / 誰が（出所チップ: 本人 = 青 `.src-own`、バディ = 琥珀 `.src-ai`、人 = 緑 `.src-record` + 名前。R-10 流用）/ 何を変えた / 結果。操作は「ここに戻す」だけ常時、バディ行だけ「違う」も。
- 既定は最新 2 行 + 「ぜんぶ見る（n）」。見出し右に「比べる」（2 行を選んで並べる）。
- 「版」の語は出さない。指す時は時刻（「10:40 のところ」）。

### 6-7 「作品に残す」ダイアログ

| 項目 | 必須 | 理由 |
| - | - | - |
| 残すところ（既定: 今。変化の列から時刻で選び直せる） | 既定あり | 試作も残せる（v1.0 367行） |
| タイトル（既定: 活動名） | 既定あり | 作品一覧の見出し |
| 気に入っているところ（1 行） | 任意 | 本人の言葉。空で残せる |
| 誰が何をした（自動。「本人 3 回 · バディ 2 回 · 田中さん 1 回」+ 各 1 行） | 表示のみ | 誇張しない記録（v1.0 371行）。編集不可、本人の言葉と混ぜない |
| ボタン「作品に残す」「やめる」 | | 共有の項目は置かない |

残した後: トースト「作品に残した」+「作品で見る」。

### 6-8 区切る・やめる時に背中を押す（確定 Q4 の落とし方）

［事実］ふじさんの回答（§11 に原文）: 本人ベースで、途中で諦める・めんどくさくなる時にやめるのもあり。ただし「うまく背中押して成長できる時は背中押したい。AI エージェントも。サポーターも背中押すけど」。押し方は「状況に応じて柔軟に」。
［事実］v1.0 443行「やめたい、疲れたと言っている → 終える、再開できるようにする。再開は本人の呼びかけや合意した条件から」、794行「『今日はここまで』を選んだ後、同じ活動への誘いを続けない」、459行「『次は何をしてくれる？』が続くときは、始める手助けと本人が関与できる機会を組み合わせる」、引き継ぎ 108行「中断: あと一つ頑張れば達成！（避ける）/ 今日はここまで（合う）」。

**原則**: 最終決定は本人。バディは「今日はここまで」「ここで一区切り」「この活動をやめる」の瞬間に、状況を見て 3 通りから 1 つ選ぶ。固定のルール表にはしない。

| 押し方 | 出し方 | 向く状況の手がかり |
| - | - | - |
| **その場で手の届く一歩を 1 つ** | ダイアログ上部に 1 文 + ボタン「{一歩}だけやってみる」（押すと作業中に戻り、今の一歩が差し替わる）。例「屋根を置くだけなら 5 分くらい。そこまでやってみる？」 | 区切りまで近い（今の一歩が残り 1 つ・次にすることが具体的）、直前の試しで結果が出ている、残り時間がある（今日の予定の次の行まで 15 分以上） |
| **次回の「続きをする」で誘う** | その場では受け止めの 1 文だけ。「次にすること」の既定文に一歩を書き、翌回の続きをするの先頭に「前はここまで。{一歩}から始める？」 | 疲れ・負荷の手がかりがある、予定の次の行が迫っている、本人が言葉で「疲れた」「めんどくさい」と言った |
| **押さずに受け止める** | 「わかった。{最後の変化}まで進んだね」の 1 文だけ。ボタン無し | 直前に一度押して断られた、本人が「やめる」を選んだ、相談列で休みたい旨がある、同じ活動で今日すでに 2 回区切っている |

**判断の手がかり（5 観点のうち主に「心理」と「体験」）**: 区切りまでの近さ（今の一歩・次にすること）/ 疲れ・負荷の手がかり（相談列の本人の言葉、直前の試しから時間が空いている、今日の作業時間の長さ）/ これまでの断り方（この活動で押して断られた回数、他の活動での反応）/ 今日の予定の残り（次の固定行・行事までの時間）。手がかりは本人の言葉と記録から取り、気持ちを断定しない（v1.0 164行「診断として扱わない」）。

**押さない条件（必ず守る）**: 断られた後に同じ瞬間で繰り返さない / 疲れ・めんどくさいの言葉があれば一歩を出さない（次回に回す）/ 「やめる」を選んだ時は一歩を出さない（あしあとから戻れることだけ伝える）/ 評価語・持ち上げ（「あと一つ頑張れば達成」「すごい」）を使わない（CONTRACT §I）/ 押した結果を記録しない（押したことは本人の活動の記録にしない。断った回数は内部の手がかりとしてだけ持つ）。

**サポーターとの接点（画面は範囲外）**: サポーターが個別画面から入れた助言（例「今日は区切りまで押してみてもよさそう」「疲れているので今日は受け止めるだけに」）は、v1.0 548〜562行の 助言 → 見立て → 試行 → 反応 → 仮説更新 の循環の「見立て」の材料になり、バディが上の 3 通りを選ぶ時の手がかりに加わる。助言は固定命令にしない（v1.0 932行）。

**モックでの見せ方（決定論 3 ケース。§13）**: (1) 今の一歩が残り 1 つ + 直前に「試す」で結果あり → 一歩を 1 つ。(2) 相談列の直近の本人発言に「疲れた」「めんどくさい」「つかれた」を含む → 受け止めて次回へ（次にすることに一歩を書く）。(3) 同じ活動で今日 2 回目の「今日はここまで」、または直前に一歩を断っている → 受け止めるだけ。

### 6-9 バディが作ったもの（棚。追加指示 1 の反映）

［事実］ふじさんの追加指示（原文、§11 末尾に全文）: 「AIが作ったもの（3Dモデル・絵・小さなゲーム）を置く場所もありません　置く場所作ろう！右側とかに。」

**役割**: バディが作った・直した・案として出したもの（3D モデル・絵・小さなゲーム・文章・コマンド列）を、作業対象に取り込む前に置く場所。候補状態（意図つき着地の「仮の案」2〜3 個）もここ。v2 までは「作業対象の 1 種」と「候補状態」に分散していたものを 1 つの置き場に統一する。

| 要素 | 見え方 | 理由 |
| - | - | - |
| 見出し「バディが作ったもの（n）」 | 右列の先頭（≤1120 では作業対象の直下）。右に「畳む」 | 数で新着が分かる |
| カード（新しいものが上） | プレビュー（線画 SVG / テキストの冒頭 / 小ゲームは静止画 + 「動かす」）/ 1 行の説明「くさび形。高さ 20」/ 琥珀の `.src-ai` チップ「バディ」+ 時刻 | 何が出てきたかを見るだけで分かる。評価語は書かない |
| カードの操作 | **これにする**（作業対象に取り込む。変化の列に「バディが{説明}を作った」琥珀 +1。カードは「採用」の薄い印で残る）/ **作り直す**（候補「作り直して / 別の案を 2 つ / ここだけ直して」→ 新しいカード）/ **違う**（カードを「見送った案」に畳む。5 秒 undo。相談列に「どこが違う？」候補）| 本人が選ぶ・直す・違うで関わる（確定 Q3） |
| 比べる | 見出し右「比べる」→ 2 枚選ぶと作業対象の上に並ぶ（変化の列の「比べる」と同じ部品） | 案を並べて見る（v1.0 1105行「二人で比べるための見本」と同じ動き） |
| 見送った案 | 列の末尾に「見送った案（n）」の畳み。開くと薄いカード + 「やっぱりこれにする」 | 経緯を消さない（v1.0 303行） |
| 空 | **列ごと出さない**（≥1121 は 2 列に戻る。≤1120 は見出しも出さない）。「バディに任せる」を押すか、意図つきで着地すると現れる | 空の棚を見せない（引き継ぎ #1） |
| 生成中（本番） | 先頭に破線枠のカード + 1 行「作っている」+「やめる」。スピナー無し（CONTRACT §I）。できたら差し替わり、相談列にも 1 行。モックでは 150ms 後に差し替え | 待ちの状態が分かり、止められる |
| 失敗（本番） | 破線枠に「今は作れなかった。見本を触るか、一緒に手で描く？」+「もう一度」 | §4 の表と同じ文 |

作業対象の「バディが作った試作」（§6-2 の 2 種目）は、棚から「これにする」で取り込まれた後の状態を指す。取り込み後も棚のカードは残り（採用の印）、作業対象で変えた分は変化の列に積まれる。棚の中身は活動に属し、`#paused` → 続きをする で戻る。

### 6-10 作品画面にキャプチャーで自分の作品を入れる（追加指示 2 の反映）

［事実］ふじさんの追加指示（原文、§11 末尾に全文）: 「作品のところにキャプチャーで自分の作品入れられたりできるといいな。それもAIが読んで何を作っているのかコンテキストに入れたり、次の提案にいかしたり、トライの提案の下地にしたり」。作品画面の全体設計は本書の範囲外のまま。ここでは **入口・追加の流れ・作るとの接続・バディの読み取りの扱い** だけを決める。

**入口**: 作品画面の見出し行の右に `.btn`「写真・スクショを入れる」（一覧の最初の位置にも同じボタンを 1 つ）。作るの入口の「写真を見せる」と同じ部品だが、行き先が違う（作る = 活動を始める / 作品 = 作品として残す）。

**流れ（小さなダイアログ 1 枚）**:

| 項目 | 必須 | 中身 |
| - | - | - |
| 画像 | 必須 | 1〜3 枚。モックは線画のダミー + `demo_media` トースト |
| タイトル | 既定あり | 既定はバディの読み取りから（「塔のある建物」）。本人が直せる |
| 何を作った？ | 任意 | 候補「建物 / 道具 / 絵 / ゲーム / 文章 / それ以外」+ 1 行。作るの「何を変えた？」と同じ部品・同じ見え方（(a) に対する答え: 揃える。候補の語だけ違う） |
| どの取り組み？ | 任意 | カタログから選ぶ（マイクラ / Scratch …）か「新しい」 |
| バディが見たこと | 表示（直せる） | 琥珀 `.src-ai` チップ「バディの見立て」+ 1〜2 行（「石とガラスの塔。屋根はまだ無い」）+ 「直す」「違う」。本人の言葉（タイトル・何を作った）とは別欄 |
| ボタン | | 「作品に残す」「やめる」。共有の項目は置かない（保存と公開は別） |

残すと: 作品が 1 件増える + **活動が 1 つ自動で生まれる**（きっかけ「作品から」、作業対象 = 外部・実物の記録、写真 1 枚 = 変化 1 つ〈本人〉）。作品の「続きを作る」でその活動の作業台へ。これで外で作ったものが作る・あしあと・次の提案と同じ線に乗る。

**バディの読み取りの扱い**:
- (b) 読み取りは「バディの見立て」として本人の言葉と分け、本人が直す・外す（v1.0 646行「本人の言葉、観察事実、AI の仮説を分け」）。写真から種類・安全性・出来を断定しない（v1.0 696行）。読み取るのは物・形・材料・工程の手がかりだけ。読み取れなければ「何を作ったか、まだ分からない。教えてくれたら覚えておくね」。
- (c) 読み取った内容は活動の「体験」（何を作ったか）と「関心」の手がかりとしてバディ側だけに残る。工場へは流さない（`docs/content-factory-design.md` §10「子どもの会話・記録はファクトリーに入らない」、v1.0 629行）。5 観点の見立てを固定プロフィールにしない（memory `project-learner-5-axes`）。
- (d) 顔・名前・名札・画面上のアカウント名などは読み取りの対象にせず、「バディの見立て」に書かない。ダイアログに 1 行「人が写っている写真は、顔が入らないものにしてね」。写真の保存は本人の作品として本人・担当サポーターの範囲（v1.0 658行）。公開は作品画面の別操作で、本書の範囲外。本番の自動検出・ぼかしは未決（実装の権限設計 v1.0 884行）。
- (e) 読み取りが次の提案に効いた時は、提案の側に**出所 1 行**を添える: 作るの仮の案 / 話すの提案カード / 今日のお題 の下に「前に入れた『塔のある建物』のスクショから」（v1.0 323行「提案カードには、何を手がかりにしたかを短く添えます」の作法を流用）。本人が「違う」と言えば、その読み取りは提案の材料から外れる。

**モック（§13）**: 作品画面は「写真・スクショを入れる」ボタン + ダイアログ + 残した 1 件のカード（タイトル・画像・バディの見立て・「続きを作る」）だけ。読み取りは決定論（ダミー画像ごとに固定の 1 行）。次の提案への反映は、作るの入口で「仮の案」の 1 枚に出所 1 行を出すところまで。

## 8. シナリオで通し検証

### A. 紙の羽（代表例 7、v1.0 1121〜1135行）— 見本 → 実物写真を同じ活動で
1. 左ナビ「作る」→ 制作中なし → 見本 3 枚。（確定 Q2 でモックの題材は工場の例に揃えたが、本シナリオは v1.0 代表例 7 の検証用として紙の羽で書く。モックの見本「回路の電気」でも同じ流れ）「動かしてみる」。
2. 作業台: 今の一歩「今: 幅を変えてみる」。見本 + スライダー「幅」「角度」+「試す」。相談「まず動かしてみる？…」。
3. 幅 20→34 とドラッグ → 「まだ試していない」。「試す」→ 結果「落ちるまで 1.2 秒 → 1.8 秒」。変化 +1（本人）。バディ「羽を広げたら…」。
4. 相談「もっと回るのにしたい」→ バディ「角度を変えると回り方が変わるよ」+「やってみる」「説明を聞く」。
5. 実物: 入力欄横「写真を見せる」→ 作業対象に写真が足される（見本の下）。「何を変えた？」→「形」+「切る線を長くした」。変化 +1（本人 + 人〈田中さん〉）。結果は本人の 1 行「ゆっくりになった」。
6. 「作品に残す」→ 残すところ = 今、タイトル「ゆっくり落ちる紙の羽」、誰が何をした「本人 2 回 · 田中さん 1 回」。
7. 翌日、作品「続きを作る」→ 同じ活動。

### B. ドアストッパー（代表例 4 / 25、v1.0 495行・1093〜1099行）— 話すから、仮の案、任せる、外部 3D
1. 話す「ドアが閉まらないようにしたい。形は AI に作ってほしい」→ bridge → 作業台。引用枠（本人の言葉）+「直す」「外す」。作業対象は空枠、**右の棚に仮の案 3 つ**（くさび / L 字 / 重り付き。バディが作った 3D 形状のプレビュー）。バディ「使う場所や大きさを、サポーターと確かめよう。近い案を選ぶか、違うところを教えて」。
2. 本人が棚の「くさび」を「これにする」→ 作業対象に取り込まれ、変化 +1（バディ「くさび形を作った」）。他 2 案は棚の「見送った案（2）」。変えられるところ「高さ・幅・すべり止め」。
3. 高さ 20→25、「試す」（プレビューが動く）→ 変化 +1（本人）。
4. 「バディに任せる」→ 候補「作り直して / 別の案を 2 つ / ここだけ直して」→「ここだけ直して」+ 言葉「すべり止めの溝を入れて」→ 棚に「作っている」→ 新しいカード → 「これにする」で変化 +1（バディ）。行に「違う」。
5. 3D プリントは外部: 「リンクを貼る」→ 作業対象 3 つ目（外部の記録）。田中さんが出力 → 「写真を足す」（人）。結果「ドアが止まった」。
6. 「作品に残す」→ 誰が何をした「バディ 2 回（案 3 つ・溝）· 本人 2 回 · 田中さん 1 回」。任せたことが参加として残り、本人の技能に付け替えない。

### C. マイクラ建築（予定表から、外部ツール、中断・再開）
1. 今日の予定 p1「建築（大きく）」の「…」→「作るで開く」→ 制作中にある → 作業台。作業対象 = 外部の記録（Minecraft + 前回のスクショ 2 枚）。今の一歩「今: 塔を 2 倍に → 次: 屋根を決める」。
2. 「スクショを足す」→「何を変えた？」→「大きさ」+「塔を 2 倍に」→ 変化 +1。バディ「前の写真と並べて見る？」→「比べる」で 2 枚。
3. 「バディに任せる」→「コマンドを作って」+「屋根を円すいに」→ 棚にコマンド列のカード（琥珀）。「これにする」で作業対象に足され、変化 +1（バディ）。相談列にも 1 行。
4. 10:50 サークル対話 → 「今日はここまで」。ダイアログ上部にバディ: 今の一歩が残り 1 つ（屋根）で直前に結果があるが、次の固定行（サークル対話）まで 15 分を切っているので **一歩は出さず**「わかった。次は屋根を置くところから始められるようにしておくね」（§6-8 ケース 2 の条件のうち「予定の次の行が迫っている」）。次にすること（既定「屋根を置く」→ 本人が「窓を増やす」に直す）/「続きがある」→ `#paused`。
5. 11:10「続きをする」→ 作業台。相談列の先頭に「前はここまで。窓を増やすから始める？」+ 止まった場所。
6. 13:30 以降、本人「もう飽きた」→「今日はここまで」。相談列に「飽きた」があるので受け止めのみ「わかった。塔を 2 倍にしたところまで進んだね」。同じ活動で今日 2 回目でもある。
7. ここで作業台が助けたこと（§6-3 の一文の検証）: 一歩の見通し / バディのコマンドが手元に残る / 前と今の比較 / 区切りと、押すか押さないかの選択。話すだけならコマンドは会話に流れて消える。

### D（短い追加）ドアストッパーで区切りに近い時
B の手順 5 の後、15:00 に「今日はここまで」。今の一歩「写真を足す」が残り 1 つ、直前に「ドアが止まった」の結果、次の固定行（15:30）まで 30 分 → バディ「写真を足すだけなら 5 分くらい。そこまでやってみる？」+ ボタン「写真を足すだけやってみる」。押すと作業中に戻る。押さずに「続きがある」なら受け止めて次回へ。断った場合、同じ日にもう一度「今日はここまで」を押しても一歩は出ない。

### E（短い追加）作品にスクショを入れて、次の提案に効く
1. 作品画面「写真・スクショを入れる」→ マイクラの塔のスクショ。タイトル既定「塔のある建物」（バディの見立て「石とガラスの塔。屋根はまだ無い」+ 直す・違う）。何を作った？→「建物」。どの取り組み？→「建築」。「作品に残す」。
2. 作品 +1、活動「塔のある建物」（きっかけ「作品から」、外部の記録に写真 1 枚）が生まれる。
3. 翌日、作るの入口: 見本 3 枚の上に制作中「塔のある建物」。bridge や思いつきで作業台に入ると棚の仮の案の 1 枚「円すいの屋根」に出所 1 行「前に入れた『塔のある建物』のスクショから」。本人が「違う」と言えば、その読み取りは提案の材料から外れる。

## 9. 「本人が選んだ・変えたこと」と結果、AI／人の記録

- 変化の 1 行が最小単位: 誰が / 何を変えた / 結果。結果は確かめられたことだけ。確かめていなければ「まだ確かめていない」で、バディは褒めない（v1.0 457行）。
- 出所は既存 3 種（R-10）を流用: 本人 = 青、バディ = 琥珀、人 = 緑 + 名前。
- 返事は「受け止める → 確認できた変化 → 次の余地」。評価語は禁止語のまま（CONTRACT §I）。
- 作品の「誰が何をした」は自動・編集不可。本人の言葉は別欄。
- 自己理解への問い: 「ここで一区切り」の後に 1 回だけ、答えなくてよい形で相談列に（v1.0 409行型）。§12 で設計者推奨として進める。
- 背中を押したこと・断ったことは本人の記録（変化の列・作品・あしあと）に残さない。断った回数は押さない条件の判定にだけ使う（§6-8）。

## 13. モックの第 1 スコープ案（確定に合わせて更新）

- `#make`（入口: 制作中 1 件 + 見本 3 枚 = マイクラのコマンド例 / Python の小さなゲーム / 回路の電気〈確定 Q2〉+ 思いつき・写真・リンク）/ `#make/<id>`（作業台）。`ROUTES` を `make/` 前方一致へ拡張。
- 作業対象 3 種: 動かせる見本（スライダー 2 本・決定論の結果。回路 = 電圧・抵抗 → 明るさの数値、マイクラ = 大きさ・ブロック → コマンド文字列、Python = 速さ・数 → 線画の静止画）/ バディが作った試作（棚から「これにする」で取り込む）/ 外部の記録（リンク文字列 + ダミー線画 2 枚。「写真を足す」「スクショを足す」は線画を 1 枚足す決定論 + 「何を変えた？」候補 5 つ + 1 行〈確定 Q5〉。本番の実入力は `demo_media` のトースト）。
- **棚「バディが作ったもの」（確定・追加指示 1。第 1 スコープに入れる）**: ≥1121 で 3 列目、≤1120 で作業対象の直下。意図つき着地で仮の案 3 枚（ドアストッパーの 3 形状の線画 SVG、または題材に応じてコマンド列・テキスト）。「バディに任せる」→ 候補 3 つ → 「作っている」の破線カード 150ms → 新しいカード（決定論で候補ごとに固定の 1 枚）。これにする（変化 +1 バディ）/ 作り直す / 違う（5 秒 undo・見送った案へ）/ 比べる。空なら列を出さない。
- 変化の列（4 つの積まれる瞬間・既定 2 行・ぜんぶ見る・比べる・ここに戻す・違う）、前に戻す（5 秒 undo）、作品に残す（→ `des3.works`）、今日はここまで（次にすること + 続きがある/一区切り + §6-8 の決定論 3 ケースのバディの一言 → `#paused` の文差し替え。`#paused` の「一歩だけやってみる」で作業中に戻る）。
- 相談列（活動の thread。決定論の返事: 着地 / 見本を開いた / 試した / 任せた / 写真を足した / 区切り 3 ケース / それ以外）。≥1121 で 3 列（棚が空なら 2 列）、951〜1120 で 2 列、701〜950 で 1 列（相談は下）、≤700 で segmented。
- 話す bridge → 活動生成 + 引用枠（直す・外す）+ 棚に仮の案 3。予定表 mine 行の「作るで開く」。
- **作品画面の最小部分（追加指示 2。第 1 スコープに「薄く」入れる）**: 作品画面は空状態 1 文ではなく、見出し + 「写真・スクショを入れる」ボタン + ダイアログ（画像ダミー・タイトル・何を作った？・どの取り組み？・バディの見立て〈決定論 1 行〉+ 直す/違う・顔の注意 1 行）+ 残した作品のカード（タイトル・線画・見立て・「続きを作る」）。残すと活動が自動生成され「続きを作る」で作業台へ。次の提案への反映は、作るの棚の仮の案 1 枚に出所 1 行「前に入れた『{title}』のスクショから」を出すところまで。作品画面の一覧・共有・詳細は外。
