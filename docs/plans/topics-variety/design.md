## 2. ふじさんの決定（2026-11-06。蒸し返さない）

- 時事のお題は、機械の検査が全部緑なら人を通さず出す。
- 重い話題（事件・事故・災害の被害・戦争・政治の対立と選挙・差別・人の死）も学年に合わせて作る。ただし人が全文を読んで承認するまで出さない。子どもの画面には「サポーターと読む」の印を付ける。
- 「誰々がこう言っている」は実在の人・組織を出典つきで書く。出典を開いて照合し、合わなければ出さない。答えのない問いには、違う立場を 2 つ以上並べる。
- お題は種類ごとに出す（ニュースから / 話し合い / 答えのない問い）。作るは複数出す。
- 作るの絵には、画像生成で作った写真風のサムネイルも使う（線画・イラスト・写真が混ざってよい）。
- 作品展示: 見られるのは同じ教室の子とサポーター / 反応ボタン + 自由文は AI の番人が先に読み、気になるものは届けずサポーターに回す / 名前は本人が決めた呼び名 / 声かけ → 作者が OK → サポーターが時間をつなぐ。

## 3. お題のストックの回り方（工場）

```
種（ニュースの RSS・ストックの題名）
   │  作る: 1 回の呼び出しで 2〜3 本（ニュースは毎日 / ほかは週 1 回）
   ▼
下書き ──▶ 確かめる
            1) 形・禁止語・重複（Worker。費用なし）
            2) 出典を Worker が開き、引用が本文にあるか照合（費用なし）
            3) 引用が主張・帰属を支えているか、重い話題か（別の呼び出し 1 回）
   │
   ├─ 全部緑 + 重くない ──▶ 出せる（自動。書くのは topicGate だけ）
   ├─ 重い話題 ───────────▶ 要確認（人が全文を読んで承認）
   └─ 赤 ─────────────────▶ 要確認（理由つき）/ 捨てる
   ▼
出せる ──▶ 毎日の予定（前日に確定。ニュース 2・話し合い 1・答えのない問い 1・作る 3）
   │
   ▼
ストック（話し合い・答えのない問い・作るは残り、30 日あけてまた出る。ニュースは 7 日で役目を終える）
   │
   ├─ 見直す（refresh）: 出典が消えた・古くなった → 前提と出典を今に合わせた子を作る。子が出せるようになった時に親は引退
   └─ 発展させる（extend）: 次の問い・別の種類（ニュース → 答えのない問い / 作るへ）の子を作る。親は残る
```

- 素材（materials）の規則「人が承認するまで出さない」は変えない。お題は素材とは別の表・別の関数で扱う。
- 親子は `lineage_id` と `parent_topic_id` で残る。本文は書き換えず、変える時は必ず子を作る。
- 費用は呼ぶ前に台帳へ取り置く。月・日・1 回の上限を同じ SQL の中で判定する。quota / 429 は失敗として記録し、次の定期まで再開しない。

## 4. 採った案・捨てた案

| 論点 | 採った | 捨てた | 理由 |
|---|---|---|---|
| お題の持ち方 | 別の表 `topics` | 素材の型 6 に載せる | 版 1 つに職人の session が要り 1 本あたり最悪 15 ドル級。公開は人の承認専用で、自動公開と衝突する |
| 出す日の決め方 | 前日に cron が行を確定 | 読む時に決定論で選ぶ | ストックが変わると同じ日でも出るものが揺れ、何を出したか後から確かめられない |
| 出典の照合 | Worker が自分で開く + 支えているかだけ別の呼び出し | 検証係（Opus Batch + web_fetch）の流用 | 素材の版・R2・制作 session に直結していて切り出せない。1 本 4 ドルの予約は釣り合わない |
| 見本の見せ方 | 6 枚を 3 枚ずつ | 6 枚を一度に並べる | 「入口の主役は見本 3 枚」（2026-11-05 確定）を保ったまま幅を出す |
| 展示の反応 | 数を出さず呼び名を並べる | いいねの数・人気順 | 件数・順位を出さない既存の約束。比べ合いにしない |

## 5. 今回作らないもの

- 工場 → app-v3 の読み込み（モックは `fetch` 禁止のまま。モックのお題は同じ形の見本データ）
- 作るの提案サムネイルを工場が自動で作る流れ（本文に `thumb_prompt` を持つところまで。生成は後続）
- 作品展示の本番の裏側（番人の呼び出し・サポーターの画面・写真に顔が写っていないかの確認）。モックは決定論の番人で動きを見せる
- 学年ごとの漢字の機械検査（小・中の 2 段の文があることまで）
