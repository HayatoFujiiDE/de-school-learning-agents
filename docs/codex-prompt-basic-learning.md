## 2. 作るもの（第 1 スコープ）

**小学算数 1 学年分の基礎学習教材**。ビルド無しの素の HTML / CSS / JS（`app-v3/` と同じ流儀: `file://` で開いて動く、外部依存は Google Fonts の 1 行だけ、`fetch` 禁止、ES2017 以内、module 不使用）。データは JS ファイルに埋め込む。

### 2-1. 単元データ

- 文科省の Excel から小学校 算数 第 1 学年の学習指導要領コードを抽出し、**コードを単元の主キー**にした `js/units.js` を作る（コード・単元名・到達点の短文・eboard 相当の並び順）
- 単元ごとに: 短い説明（小学生表示）+ 詳しい説明（中学生・大人表示）、練習問題 5〜10 問（機械採点できる形: 数値入力・選択・並べ替え）、「バディに説明してみる」の問いかけ 1〜2 本
- 最初の中身はあなたが作ってよい。ただし **各単元に `claims`（説明で使う事実の一覧）と `adapt-rules`（言い換えてよい範囲・変えてはいけない事実）を必ず付ける**。後でコンテンツファクトリーがこの形で中身を差し替える

### 2-2. 画面

1. 単元一覧（eboard 型: 領域 → 単元の並び。各単元に達成率 % の帯）
2. 単元画面: 説明（短い / 詳しい の切替）→ 練習問題 → 結果 → 「バディに説明してみる」の入口
3. 達成率: 練習問題の正答と「説明できた」の両方から計算。**子どもにも % を見せる**。計算式はあなたが決めて `README` に書く
4. ゲーム的な形を最低 1 つ（例: お題・クイズ・「なし」を当てる）。形は提案してよい
5. 関心別の入口: `app-v3/js/data.js` のカタログ（マイクラ / プログラミング / ものづくり など）のカテゴリを使い、同じ単元に 2 つ以上の「入口の例」を持たせる（例: 「10 のまとまり」をマイクラのブロック 10 個で / ダンボールの箱 10 個で）
6. 小学生表示 / 中学生表示の切替を最初から持つ

### 2-3. 守ること（契約）

- 子ども画面で **「点数・ランキング・順位・評価・成績・レベル・集中力・得意・苦手・上手・成長・データがありません・学びのバディ」を使わない**（`CONTRACT-v3.md` §J）。「達成率」は使ってよい
- 呼び名は「バディエージェント」（短縮「バディ」可）
- 「毎日やる」を義務にしない。休む・今日は終える、を選べる
- 本人の記録は `localStorage` だけに置く（`bl.*` キー、try/catch）。外へ送らない
- 説明より先に触れるもの（操作できる例・図）を置く
- 未確認の事実を説明に書かない。算数の事実は `claims` に列挙し、説明文はそこから外れない
